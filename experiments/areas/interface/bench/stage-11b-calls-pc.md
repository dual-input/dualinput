# Stage 11b outline: settled calls from the PC session

The calls settled in the stage 11b PC session, from 2026-10-25 to 2026-10-31, one dated bullet per call, with the user's words where they gave them, and what was tried and dropped.
[The cloud session's file](stage-11b-calls-cloud.md) holds the calls after these, and [the interface's tentative decisions](../../../../record/areas/interface/decisions.md) hold what both settled, so a value or a word here that a later bullet changes no longer holds.

## Walk 1: install to the first sim start

- Installer: Velopack's Setup.exe as is (our splash image with its progress bar), no MSI, no setup program of our own.
- First run (Setup.exe starts the app with its first-run flag): a small window, "Welcome to Dual Input", a line pointing to the EFB app (open the EFB at the world map or in a flight), Dismiss as its only action.
- Applying an update: Velopack's stock progress dialog, not silent, so the pilot sees what's happening while Update.exe has our programs stopped.
- The desktop window loses Check now, Install now, and the update's states; from the tray it shows the 24 hours of CPU and memory.
- Updates stay out of the core: the desktop app serves the update's state on a fixed 127.0.0.1 port, and the EFB app connects to it directly, showing a new version and asking to restart the sim to install; the desktop app then closes the sim, installs, and starts the sim again.
  If another program holds the port, the EFB app shows no update; a developer's second desktop app runs without the server.
  Open: the port number; how the desktop app closes the sim cleanly (unverified, needs a check in the sim); starting the Store edition (unverified).
- Follows from it: the join refusal for an older version can offer "Restart to update" in the EFB app.
- Tray icon: left click opens the window; right click shows a native menu: a usage line with the tray app's own figures (refreshed on a timer, clickable, opens the window), Settings… (opens the window), a separator, and Quit, which asks once as the record has it.
  The window: the 24 hours of figures (the tray app's and the core's), a note on what the app does for the pilot and what quitting costs, in concrete terms, and Start with Windows; every other setting stays in the EFB app.
  The goal: persuade the pilot to keep it running and starting with Windows, without hiding Quit. Details at build time.
- Firewall: no UI of the desktop app's own. The first run shows the UAC prompt, as designed. If the rule is missing or blocked (the pilot declined), the EFB app shows a red status with a fix action, which the desktop app carries out with the UAC prompt.
  So the desktop app's fixed-port link carries its own state to the EFB app: the update's and the firewall rule's.
  Known cost: the UAC prompt from the fix action appears on the desktop while the sim is in front.
- A sim that has never run (no `UserCfg.opt`): the welcome window says instead (user's wording):
  "Looks like MSFS 2024 hasn't run on this PC yet, so Dual Input can't install its sim components."
  1. Start MSFS 2024, then close it.
  2. Start it again, and you'll find Dual Input in the EFB.
