## What matters most for our design

1. **TURN wrapping is our job.** When the agent sends from a relayed candidate, `Transmit.source` is the relayed address. The candidate's base is set to that address, and nothing in the send path checks the candidate's kind. So our layer has to spot "source == our relayed address" and wrap the packet for TURN. Firezone's code does exactly this. [SRC]
2. **Packets that arrive through TURN.** We must hand them to the agent with `source` = the peer's address and `destination` = our relayed address. The agent drops a binding request unless its `destination` equals the address of one of our local Host or Relayed candidates. [SRC]
3. **The agent does no STUN-server queries and no TURN.** Its parser rejects a Binding success response that has no MESSAGE-INTEGRITY, so it can't parse typical public STUN server replies. Those replies must go to our own STUN client. [SRC] That public servers usually omit MESSAGE-INTEGRITY is [UNVERIFIED].
4. **Path choice is by candidate priority, not measured round-trip time.** The controlling side re-nominates whenever a higher-priority pair succeeds, or when the nominated pair fails. With default settings a dead pair is detected in about 21.5s, and every timing value can be changed. [SRC] and [INFERENCE]
5. **There is no Failed state and no end-of-candidates.** A pair that fails is deleted and isn't retried on its own. [SRC]
6. **We should generate the ICE credentials ourselves.** `IceCreds::new()` draws them from `fastrand`, which is not a cryptographic random number generator. [SRC]
7. **`Transmit` isn't re-exported by `is`.** It is `str0m_proto::Transmit`. [SRC]

## 5. Incoming packets

**The functions.**
- The entry point is `handle_packet(&mut self, now: Instant, packet: StunPacket) -> bool` (L1163-1189). It returns false when the packet isn't accepted. [SRC]
- `StunPacket<'a> { pub proto: Protocol, pub source: SocketAddr, pub destination: SocketAddr, pub message: StunMessage<'a> }` is at stun.rs L1453-1464. [SRC]
- We parse first, with `StunMessage::parse(buf: &'a [u8]) -> Result<StunMessage<'a>, StunError>` (stun.rs L121). [SRC]

**How the agent decides a STUN message is for it.** The public helper is `accepts_message(&self, &StunMessage<'_>) -> bool` (L1063-1158). `handle_packet` calls it internally. It returns false for any of these: [SRC]
- a Binding indication
- an unknown method or class
- any TURN method
- a request whose USERNAME left half isn't our ufrag
- a request whose right half doesn't match the remote ufrag, once that is known
- a message that fails the integrity check
- a response whose transaction ID it doesn't recognize

**Non-STUN data never reaches the agent, because the types prevent it.** [SRC]
- The parser checks the length is a multiple of 4, that the length plus 20 equals the buffer length, and the magic cookie (stun.rs L122-139).
- It masks off the top two bits of the type field rather than checking them (L126).
- It requires a binding request to carry MESSAGE-INTEGRITY, a USERNAME containing `:`, and PRIORITY (L176-190).
- It parses FINGERPRINT but doesn't verify it (L1037-1043).
- Demultiplexing by first byte is our job. str0m's own test is `byte0 < 2 && len >= 20` (src/io/mod.rs L125-126).

**Packets that arrived through TURN.** [SRC]
- A binding request is accepted only if `destination` equals the `addr` of a local Host or Relayed candidate with the same protocol. Otherwise the agent logs "Discarding STUN request on unknown interface" (L1448-1465).
- So we present `destination` = our relayed address and `source` = the peer's address.
- For responses the agent doesn't check `destination`. It finds the pair by transaction ID and matches XOR-MAPPED-ADDRESS against local candidates' `addr` (L1846-1850). That address will be our relayed address.
- Firezone does the same (node.rs L563-564): "For our agents, it is important what the initial "destination" of the packet was."

**Packets that arrived directly.** `destination` must be the host candidate's address. [SRC] With one socket bound to the wildcard address we need each datagram's destination IP. [INFERENCE] I didn't check whether quinn-udp provides it on Windows. [UNVERIFIED]

**Choosing where to send data.** We use the last `NominatedSend`; its doc says "The application should always use the values of the last emitted event to send data." (L283-285). [SRC] Both roles emit it, from `evaluate_nomination` (L1923-1968). [SRC]

**Peer-reflexive candidates and other source addresses.**
- The agent creates peer-reflexive candidates silently and emits no event for them (L1542-1551, L1891-1906). [SRC]
- `DiscoveredRecv` is the only signal of a new remote source address. [SRC]
- `has_viable_remote_candidate(addr) -> bool` (L514-519) says whether data from an address belongs to a pair that has succeeded. [SRC]

**States** (L185-220). [SRC]
- The states are New, Checking, Connected, Completed, and Disconnected. There is no Failed or Closed.
- `is_connected()` is true for Connected and Completed (L224-227).

**Transitions,** from `evaluate_state` (L2034-2099). [SRC]
- From New, the agent moves to Checking.
- From Checking or Disconnected:
  - with a nominated pair, to Connected if other pairs are still possible, otherwise to Completed;
  - with nothing nominated and nothing possible, to Disconnected;
  - otherwise to Checking.
- From Connected, with nothing nominated, to Checking or Disconnected.
- From Completed, when new pairs become possible, to Connected.

**Completed rarely appears.** Nominated pairs don't count as "still possible" (L2040-2046). So with several working pairs the state stays Connected and never reaches Completed. We should test with `is_connected()`. [INFERENCE]

## 7. Timers and settings

**Polling.**
- `poll_timeout(&mut self) -> Option<Instant>` (L1305-1341) returns `None` until `handle_timeout` has run once. If anything is queued it returns `last_now + Ta`. Otherwise it returns the earliest next check, but no sooner than `last_now + Ta`. With no pairs at all it returns `last_now + 3s`. [SRC]
- `handle_timeout(&mut self, now)` handles at most one queued request, or one pair check, per call (L1218-1222, L1268-1284). So checks are paced at one per Ta. [SRC]

**Constants and setters.** [SRC]

| Value | Default | Where | Setter |
| --- | --- | --- | --- |
| Pacing interval (Ta) | 50ms | agent.rs L345 | `set_timing_advance(Duration)` L404 |
| Initial retransmission timeout (RTO) | 250ms | stun.rs L67 | `set_initial_stun_rto` L428 |
| Maximum RTO | 3000ms | stun.rs L70 | `set_max_stun_rto` L450 |
| `DEFAULT_MAX_RETRANSMITS` | 9 | stun.rs L12 | `set_max_stun_retransmits` L465 |
| Candidate pair limit | 100 | agent.rs L918 | `set_max_candidate_pairs` L379 |
| Queued request limit | 100 | agent.rs L1415 | none |
| `RECENT_BINDING_REQUEST` | 15s | pair.rs L12 | none |
| MTU target / warning size | 1150 / 1280 bytes | proto lib.rs L4, L13 | `set_mtu` agent.rs L354 |

- The source comment on the maximum RTO reads: "libwebrtc uses 8000 here but we want faster detection of gone peers." [SRC]
- `set_local_preference` (L478), `set_ice_lite` (L394), and `set_control_tie_breaker` (L372) are the other setters. [SRC]
- Timing changes take effect immediately (L482-486; test at lib.rs L1037-1091). [SRC]

**Retransmit delay.** `stun_resend_delay(n) = min(initial_rto << min(n-1, max_retransmits), max_rto)` (stun.rs L37-48). Each retry is a new transaction with a new transaction ID. The agent keeps the last `max_retransmits` attempts, so a late response to one of those still counts (pair.rs L284-297). [SRC]

**Time to detect a dead pair.** `ice_timeout()` is `timeout()`, which is the sum of `delay(2..=max_retransmits)` plus `delay(max_retransmits)` (stun.rs L23-29). [SRC]
- With defaults that is 500 + 1000 + 2000 + 3000×5 + 3000 = **21.5s**. [INFERENCE: arithmetic]
- Firezone's test asserts 16.5s for its own settings (12 retransmits, 1500ms maximum RTO, 250ms initial RTO), which matches the formula (firezone node.rs L156-162, L2291-2297). [SRC]
- A pair that never gets an answer is pruned after roughly 21.75s. [INFERENCE]

**Keepalive.**
- Every pair, not only the nominated one, keeps being checked. The next check is due at the last check plus `delay(number of attempts)`, and never more than `max_rto` later (pair.rs L431-465). [SRC]
- In steady state that is about one check every 3s, per pair, from each side. [INFERENCE]
- When the oldest unanswered check is more than `max_rto/2` old, the delays restart from the unanswered count (pair.rs L441-450). [SRC]
- A pair counts as alive while the peer has sent us a binding request within the last 15s (pair.rs L476-480). [SRC]

**When the nominated pair dies.** [SRC]
- `handle_timeout` deletes pairs that have failed (L1229-1246) and then runs `evaluate_nomination` again.
- The controlling side switches to the highest-priority surviving pair that has succeeded and emits a new `NominatedSend` (L1926-1932, L1958-1966). The controlled side follows the new USE-CANDIDATE.
- If no pair survives, the state becomes Disconnected (L2076-2085). No event cancels the last `NominatedSend`.

**Recovering a failed pair.**
- A failed pair is deleted, not marked; the comment is at pair.rs L78-86. [SRC]
- A binding request from the peer recreates the pair (agent.rs L1568-1588). [SRC]
- So do new candidates, or a call to `recreate_candidate_pairs()`. [SRC]
- Re-adding an identical local candidate is rejected. `same_kind` counts the existing candidate, so the new one gets a lower priority and is logged as "Reject redundant candidate" (L632-672). [INFERENCE]
- Re-adding a remote candidate after its pairs are gone does create pairs again (L754-824). [INFERENCE]
- Firezone switches to longer "idle" timing when idle (`client_idle`: 25s RTO, 4 retransmits; node.rs L164-170). [SRC]

## 8. IPv6

- The agent pairs IPv4 only with IPv4 and IPv6 only with IPv6 (L700-706, L815-821). [SRC]
- The default local preference (preference.rs L13-78) gives each candidate kind its own range: relayed 0-16384, server-reflexive to 32768, peer-reflexive to 49152, host to 65536. Inside each range IPv6 gets the odd values, so it sits 1 above IPv4. [SRC]
- A relayed candidate whose relay address and local address are different IP families takes a penalty of 1000. A test shows a relayed IPv4-to-IPv4 pair winning over an IPv6 relay reached over IPv4 (lib.rs L968-1035). [SRC]
- IPv6 link-local addresses are accepted (candidate.rs L628-635). [SRC]
- Unique local addresses (ULA, fc00::/7) get no special handling; I searched and found none. [SRC]
- Loopback addresses are accepted, although the doc comments at L618-619 and L727-728 say they "cause an error". [SRC]
- `set_local_preference(impl LocalPreference)` lets us plug in our own policy, for example demoting ULA or link-local addresses. It must be set before any local candidate is added (L475-480). [SRC]

## 9. Nomination

**Regular nomination only, made by the controlling side.**
- The agent adds USE-CANDIDATE only when `self.controlling && pair.is_nominated()` (L1733). [SRC]
- It nominates a pair only after that pair has succeeded (L1926-1932, L1953-1956). [SRC]
- In the `host_host` test the controlling side sends 2 requests: a check, then the nomination (lib.rs L277-286). [SRC]

**The controlled side.** It nominates a pair when USE-CANDIDATE arrives (L1627-1633). It rejects USE-CANDIDATE while it is itself controlling (L1485-1489). [SRC]

**The selected pair can change.** README L76-77 says "Nomination is not final", and docs/ice.md L120-140 explains why. [DOC] [SRC]
- `evaluate_nomination` runs after every response the controlling side receives (L1915-1917) and on every `handle_timeout` (L1227).
- It picks the highest-priority pair that has succeeded, and switches when that priority differs from the current one (L1942-1950).
- It never looks at round-trip time.
- A test confirms a lower-priority pair added later doesn't take over (lib.rs L763-807).
