### Corrections to the design statement

- **QUIC is not in 128..191.** RFC 9443 assigns QUIC to 80..127 and 192..255. 128..191 belongs to RTP/RTCP. QUIC short headers can also fall in 64..79, which overlaps TURN ChannelData. RFC 9443 §2 resolves the overlap by source address: a packet in that range is ChannelData only if it comes from the TURN server's address and port. [DOC] https://www.rfc-editor.org/rfc/rfc9443.txt lines 119-134 and Figure 3 (lines 194-208).
  - `TurnClientUdp::recv` already applies that source-address check (udp.rs:187-197 `@52209bf`). [SRC]
- **quinn greases the QUIC bit by default, and RFC 9443 forbids that for multiplexed sockets.**
  - RFC 9443: endpoints that multiplex their socket "MUST NOT send the grease_quic_bit transport parameter" (lines 98-100). [DOC]
  - quinn-proto 0.11.19 has `grease_quic_bit: true` by default (`quinn-proto/src/config/mod.rs:63`, setter `EndpointConfig::grease_quic_bit` at :127-135, tag `quinn-proto-0.11.19`). We have to set it to false. [SRC]

- A relayed address whose family wasn't requested is not recorded. If none matches, the allocation fails (protocol.rs:1318-1369).

- No 4-byte padding over TCP, in either direction. Searching the crates finds no padding or alignment code. RFC 8656 §12.5 says ChannelData over TCP/TLS "MUST be padded to a multiple of four bytes" (rfc8656.txt lines 2364-2370). [INFERENCE] TCP/TLS channel interop with coturn or Cloudflare could break; not measured.
- Over UDP, trailing padding from a server is tolerated (`ChannelData::parse` uses `data[4..4+len]`).

**Send and Data indications**
- Outgoing Send indications come from `DelayedMessage::for_server` (transmit.rs:191-240).
- Incoming Data indications are parsed, including the ICMP attribute, but only from peers with a permission (protocol.rs:551-606).

**Allocation refresh**
- Automatic, inside `poll_transmit`. It always requests LIFETIME 1800 (protocol.rs:1990-2005).
- The refresh fires at expiry minus 60 s, or at lifetime/2 if the lifetime is 120 s or less (protocol.rs:2507-2514, `EXPIRY_BUFFER` 60 s at :50).
- A REFRESH response granting less than 600 s is ignored with a warning (protocol.rs:741-747, `MIN_LIFETIME` :64, PR #88).
- `delete(now)` sends REFRESH with LIFETIME 0, and a 437 reply to it counts as success (protocol.rs:2067-2088, :716-719).

**Permission and channel refresh**
- Automatic. Permissions use `PERMISSION_DURATION` 300 s and refresh at 240 s. Channels use `CHANNEL_DURATION` 600 s and refresh at 540 s (protocol.rs:52-56, :2007-2052).

### 3. The sans-IO usage pattern

**Construction**
- `TurnClientUdp::allocate(local_addr: SocketAddr, remote_addr: SocketAddr, config: TurnConfig) -> Self` (udp.rs:74).
- `TurnConfig::new(TurnCredentials::new(username: &str, password: &str))` (api.rs:178; `turn-types/src/lib.rs:90`).
- Optional `set_request_retransmits(initial, max, retransmits, final_timeout)` (api.rs:311).

**Receiving**
- `recv<T>(&mut self, transmit: Transmit<T>, now: Instant) -> TurnRecvRet<T>` (api.rs:114).
- `TurnRecvRet` is `Handled`, `Ignored(Transmit<T>)`, `PeerData(TurnPeerData<T>)` (with `.peer: SocketAddr`, `.transport`, and `.data()`; zero-copy range into your buffer), or `PeerIcmp{..}` (api.rs:386-417, :432).
- `poll_recv` always returns `None` for UDP (udp.rs:228).

**Sending**
- `poll_transmit(now) -> Option<Transmit<Data<'static>>>` (api.rs:127). Requests are paced at no more than one per 50 ms (`MIN_STUN_REQUEST_CADENCE`, protocol.rs:60, :1959-1975).

**Send to a peer through the relay**
```rust
fn send_to<T: AsRef<[u8]> + Debug>(&mut self, transport: TransportType, to: SocketAddr, data: T, now: Instant)
    -> Result<Option<TransmitBuild<DelayedMessageOrChannelSend<T>>>, SendError>;   // api.rs:103-109
```
- UDP always returns `Some` (udp.rs:178).
- The result is ChannelData if a confirmed, unexpired channel exists for that exact peer `SocketAddr`; otherwise it's a Send indication (protocol.rs:1534-1549).
- `from` is the local address and `to` is the TURN server.
- It returns `Err(SendError::NoPermission)` when there's no permission for `to.ip()` (protocol.rs:1500-1502).
- Materialize the bytes with `.build() -> Transmit<Vec<u8>>` or `.write_into(&mut [u8])`. With `write_into`, pass a slice of exactly `.data.len()` bytes: some variants use `copy_from_slice` (api.rs:597-600, :649-656).

**Timers and events**
- `poll(now) -> TurnPollRet::{WaitUntil(Instant), AllocateTcpSocket{..}, TcpClose{..}, Closed}` (api.rs:346-371).
- `poll` returns `WaitUntil(now)` while events are queued (protocol.rs:1595-1597), so drain `poll_event()` before sleeping.
- `poll_event() -> Option<TurnEvent>`. Variants: `AllocationCreated(TransportType, SocketAddr)`, `AllocationCreateFailed(AddressFamily)`, `PermissionCreated` and `PermissionCreateFailed(TransportType, IpAddr)`, `ChannelCreated` and `ChannelCreateFailed(TransportType, SocketAddr)`, `TcpConnected` and `TcpConnectFailed` (api.rs:445-463).
- `Instant` is `sans_io_time::Instant`, re-exported as `turn_client_proto::stun::Instant`. `Instant::from_std(base)` gives the time elapsed since `base`.

**Minimal sketch** (not compiled; every name is from the source above):
```rust
use turn_client_proto::prelude::*;                       // TurnClientApi, DelayedTransmitBuild
use turn_client_proto::api::{TurnConfig, TurnEvent, TurnPollRet, TurnRecvRet};
use turn_client_proto::udp::TurnClientUdp;
use turn_client_proto::stun::{agent::Transmit, Instant};
use turn_client_proto::types::{TransportType, TurnCredentials};

let base = std::time::Instant::now();
let mut turn = TurnClientUdp::allocate(local_addr, turn_server,
    TurnConfig::new(TurnCredentials::new(&user, &cred)));
// driver: TurnPollRet::WaitUntil(t) => sleep until t or a packet/command; Closed => tear down
while let Some(ev) = turn.poll_event() { if let TurnEvent::AllocationCreated(_, relayed) = ev { /* ICE relay candidate */ } }
while let Some(t) = turn.poll_transmit(Instant::from_std(base)) { sock.send_to(&t.data, t.to).await?; }
// every datagram on the shared socket:
match turn.recv(Transmit::new(&buf[..n], TransportType::Udp, from, local_addr), Instant::from_std(base)) {
    TurnRecvRet::PeerData(d) => { /* d.peer, d.data(): QUIC or ICE STUN from the peer */ }
    TurnRecvRet::Ignored(t) => { /* not TURN: demux by first byte to ICE / quinn */ }
    _ => {}
}
turn.bind_channel(TransportType::Udp, peer, Instant::from_std(base))?;     // also installs a permission
if let Some(tb) = turn.send_to(TransportType::Udp, peer, quic_bytes, Instant::from_std(base))? {
    let out = tb.build(); sock.send_to(&out.data, out.to).await?;          // out.to == TURN server
}
```

### 4. Sharing a UDP socket

**The crate does not need to own the socket**, since it does no I/O.

`recv` returns `TurnRecvRet::Ignored(transmit)`, with the original buffer handed back, in these cases [SRC]:
- `transmit.to` isn't the construction `local_addr`.
- `from` isn't the TURN server.
- The transport doesn't match.
- The packet parses as neither STUN nor ChannelData (udp.rs:187-203).
- It's a STUN response to an unknown transaction, so stun-proto `handle_stun_message_with_time` returns false (`agent.rs:352-359`). That covers an ICE binding response coming back from `turn.cloudflare.com`.
- It's ChannelData on an unknown or still-pending channel (protocol.rs:1127-1146).
- Tested: `test_client_receive_offpath_data` and `turn_unparseable_data` (`tests/udp.rs:144-163`, `api-tests/src/lib.rs:1143-1159`).

[INFERENCE] Pass the same `to` address you gave `allocate`. A dual-stack `[::]` socket reports IPv4 peers as `::ffff:a.b.c.d`, which won't equal an IPv4 `remote_addr`.

[INFERENCE] Size the QUIC MTU for the wrapper: 4 bytes for ChannelData, or about 36 bytes plus padding for a Send indication (RFC 9443 line 113 cites "36-byte STUN overhead").

- Yes, it's rice-proto's TURN client (`rice-proto/src/turn.rs:23-37` @v0.4.3).
- GStreamer's C `webrtcbin` (gst-plugins-bad) does not use it. It uses the libnice backend: `gst-libs/gst/webrtc/nice/` is the only ICE backend directory found.
- `gst-plugins-rs` `net/webrtcbin2` ("GStreamer plugin for low level WebRTC elements", 0.16.0-alpha) depends on `librice = { version = "0.4.3", ..., features = ["runtime-tokio"] }` (`net/webrtcbin2/Cargo.toml` and `Cargo.lock` on main).
  - That chain runs librice → rice-c → the system rice-proto C library → turn-client-proto.
- GitLab code search needs a login, so this comes from the manifests and lock file only.

### 6. webrtc-rs TURN crates

**`turn` 0.17.2** [SRC]
- It exists: published 2026-07-20 by rainliu, license `MIT/Apache-2.0`, 7.48M total downloads.
- Repository: webrtc-rs/webrtc, published from commit `1da3fe8ee84db8d266322cbcfcb357c745959a8e` ("bump version to v0.17.2", tag `v0.17.2`, branch `v0.17.x`, `path_in_vcs turn`).
- **API style: async on tokio.**
  - Dependencies include `tokio ^1.32`, `async-trait`, and `webrtc-util` (conn).
  - Public API: `Client::new(ClientConfig).await`, `listen()`, `allocate() -> impl Conn`, `close()`, `send_binding_request*` (`turn/src/client/mod.rs:607-646`).
- **It can't share our socket without a wrapper.** `ClientConfig.conn: Arc<dyn Conn>`. `listen()` spawns the read loop itself and silently drops non-TURN packets (mod.rs:224-330). `handle_inbound` is private to `ClientInternal`.
- **Supports:** ChannelData, padded to 4 bytes always (`proto/chandata.rs:7-50`). Data goes as Send indications until the binding is ready (`relay_conn.rs:294-358`).
- **Refresh:** allocation at lifetime/2, permissions every 120 s, each with up to 3 retries on 438 (`relay_conn.rs:27-28`, :85-86, :587-621). Channels re-bind on a send after 5 minutes (:313-351).
- **Missing:** TCP or TLS to the server and REQUESTED-ADDRESS-FAMILY. The client always requests `PROTO_UDP` and has no stream framing (mod.rs:42, :527, :553).

**`rtc-turn` 0.21.0** [SRC]
- Published 2026-09-19 from github.com/webrtc-rs/rtc (tag v0.21.0).
- It's the sans-IO rewrite: "The Sans-I/O TURN client" (`rtc-turn/src/client/mod.rs:1`).

**Issues #263 and #267** in webrtc-rs/rtc [SRC]. Both are open and target `rtc-turn` 0.21.0 and master, not `turn` 0.17.2:
- **#263** (opened 2026-09-27, no comments): an allocation Refresh that gets 438 is not re-sent, so relayed connections drop at about 65 minutes. The reporter reproduced it twice. [MEASURED-BY-OTHERS]
  - It doesn't apply to `turn` 0.17.2, which returns `ErrTryAgain` on 438 and retries up to 3 times (`relay_conn.rs:502-504`, :590-602).
- **#267** (opened 2026-10-03): a ChannelBind refresh that gets 438 deletes the binding. Rebinding with a new channel number then gets 400s, and ICE fails at about 10m40s (3 of 3 sessions). The reporter's patch kept an 82-minute session up, and maintainer rainliu replied "yes, please submit a PR". [MEASURED-BY-OTHERS]
  - [INFERENCE] `turn` 0.17.2 fails differently: any ChannelBind non-success becomes `ErrUnexpectedResponse`, which marks the binding `Failed` and keeps it. `bind()` never reads the new nonce, and a `Failed` binding is never re-bound, so traffic to that peer silently falls back to Send indications (`relay_conn.rs:248-308`, :330-351, :537-582).

### 7. Cloudflare Realtime TURN [DOC]

**Hosts and ports** (https://developers.cloudflare.com/realtime/turn/ "Service address and ports"; updated 2026-09-25)

| Protocol | Host | Primary port | Alternate port |
|---|---|---|---|
| STUN | stun.cloudflare.com | 3478/udp | |
| TURN over UDP | turn.cloudflare.com | 3478/udp | 443/udp |
| TURN over TCP | turn.cloudflare.com | 3478/tcp | 80/tcp |
| TURN over TLS | turn.cloudflare.com | 5349/tcp | 443/tcp |

- A note on the generate-credentials page mentions an "alternate port 53", but neither the port table nor the example response lists 53. The docs are inconsistent.
- TLS 1.1 through 1.3 are supported.
- The FAQ says `turn.cloudflare.com` also answers STUN binding requests.
- Custom domains work for UDP and TCP, not TLS (/custom-domains/).

**Credentials** (/generate-credentials/)
- Create a TURN key in the dashboard or API. That key is not usable as a credential itself.
- Mint per-session credentials with `POST https://rtc.live.cloudflare.com/v1/turn/keys/$TURN_KEY_ID/credentials/generate-ice-servers`, header `Authorization: Bearer $TURN_KEY_API_TOKEN`, body `{"ttl": 86400}`.
- It returns 201 with `iceServers` (urls, `username`, `credential`).
- The `/credentials/generate` endpoint (on /replacing-existing/) also accepts a `customIdentifier`.
- `/credentials/$USERNAME/revoke` returns 204.
- Maximum TTL is 48 hours.
- An allocation has no maximum duration. Expired credentials are cut off "after a short delay" (/faq/).

**Feature matrix** (/rfc-matrix/, updated 2026-04-21; plus /faq/)
- Supported: UDP, TCP, and TLS to the server, TURN REST API, ALPN.
- Not supported: DTLS, RFC 6062 TCP relaying, RFC 6156 IPv6 relays, OAuth, MICE.
- Clients can reach the server over IPv6, but it issues **IPv4 relay addresses only** and ignores `REQUESTED-ADDRESS-FAMILY`.
  - [INFERENCE] With `set_address_family(IPV6)`, `turn-client-proto` would reject the IPv4 relay and fail (protocol.rs:1318-1369). Keep the default IPv4-only config.
- ChannelBind is implied supported: the FAQ names "CreatePermission or ChannelBind requests". ChannelData isn't stated explicitly.
- CreatePermission and ChannelBind are denied for private, loopback, link-local, multicast, and BYOIP addresses.
  - [INFERENCE] Don't request permissions for the peer's host candidates. Expect `PermissionCreateFailed` if you do.

**Limits and pricing**
- Per-allocation limits: more than 5 new IPs per second, more than 5-10 kpps, more than 50-100 Mbps. Exceeding them drops packets (landing page "Limits").
- No specific MTU limit.
- $0.05 per GB, counted on egress from Cloudflare to the TURN client, TURN overhead included.
- Free tier: 1,000 GB per month, shared with the SFU (/sfu/platform/pricing/, updated 2026-09-22; /faq/).
- STUN is free.
